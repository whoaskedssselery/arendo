# API-документация приложения Arendo

Команда №5 «ЧЕКЛИ». Аналитик: Коржнев М.Д.

## 1. Общие сведения

* Стиль: REST, формат данных JSON, кодировка UTF-8.
* Базовый адрес: `/api/v1`.
* Интерактивная документация (Swagger UI): `/api/docs`.
* Машиночитаемый контракт: `docs/api/openapi.yaml` (OpenAPI 3.0).
* Количество операций: 40.

## 2. Аутентификация и роли

Вход по email и паролю выдаёт пару токенов: access (JWT, 15 минут) и refresh (30 дней, меняется при каждом обновлении). Защищённые запросы передают заголовок `Authorization: Bearer <access-токен>`. Роли: арендатор (tenant), владелец (owner), администратор (admin). Помимо роли сервер проверяет, принадлежит ли ресурс пользователю.

## 4. Интеграция

### 4.1. Как клиент подключён к API

Клиент на React обращается к серверу через `fetch`. Все запросы проходят через одну функцию `request` в `frontend/src/api.ts`: она добавляет токен и тип содержимого, обрабатывает ошибки и обновляет сессию. Кэш и повторные запросы ведёт TanStack Query.

В Docker и при разработке клиент и API находятся на одном адресе: Nginx (или Vite) перенаправляет `/api` на сервер, поэтому CORS не нужен. Для отдельного домена задают `VITE_API_URL` на клиенте и список разрешённых адресов `CORS_ORIGINS` на сервере. Без этой переменной чужим сайтам доступ не разрешён.

### 4.2. Последовательность работы

1. `POST /auth/register` или `POST /auth/login` — получить токены.
2. `GET /rooms`, `GET /rooms/{id}`, `GET /rooms/{id}/calendar` — выбрать помещение и время.
3. `POST /bookings` — создать аренду.
4. `GET /bookings` — следить за статусом; `POST /bookings/{id}/cancel` или `/complete`.
5. При ответе 401 один раз вызвать `POST /auth/refresh` и повторить запрос. Использованный refresh-токен повторно отправлять нельзя: сервер закроет всю сессию.
6. `POST /auth/logout` — завершить сессию.

### 4.3. Примеры

Вход:

```
POST /api/v1/auth/login
Content-Type: application/json

{ "email": "user@example.com", "password": "<пароль>" }
```

```
200 OK
{
  "accessToken": "<JWT>",
  "refreshToken": "<строка>",
  "user": { "id": 4, "fullName": "Анна Кузнецова", "role": "tenant" }
}
```

Создание аренды из JavaScript:

```
const response = await fetch("/api/v1/bookings", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${accessToken}`,
  },
  body: JSON.stringify({
    roomId: 1,
    startAt: "2026-12-05T10:00:00Z",
    endAt: "2026-12-05T12:00:00Z",
  }),
});
```

Фото и иконки отправляются формой `multipart/form-data` с полем `file`; заголовок `Content-Type` браузер ставит сам.

### 4.4. Форматы данных

* Дата и время — строка ISO 8601 в UTC; интерфейс показывает их в поясе устройства.
* Деньги — числа в рублях.
* Списки разбиты на страницы параметрами `page` и `pageSize`.

### 4.5. Обработка ошибок

Ошибка приходит в JSON с полями `statusCode` и `message`; при ошибке проверки полей добавляется список `errors`.

| Код | Значение | Что делает клиент |
|---|---|---|
| 400 | неверный запрос | показывает сообщение |
| 401 | нет или просрочен токен | обновляет сессию, при неудаче просит войти |
| 403 | нет прав | сообщает о недостатке прав |
| 404 | не найдено | предлагает вернуться в каталог |
| 409 | конфликт: занятое время, недопустимый статус | предлагает выбрать другое время |
| 413 | файл слишком большой | просит выбрать файл поменьше |
| 422 | ошибка проверки данных | показывает, что исправить |
| 429 | слишком много запросов | просит подождать |

Если сервер недоступен, клиент показывает сообщение об отсутствии связи и кнопку «Повторить».

### 4.6. Кэширование ответов

Публичные ответы приходят с `ETag` и `Cache-Control: public, no-cache` и могут сжиматься gzip. При повторном запросе с `If-None-Match` сервер отвечает `304`. Личные ответы помечены `no-store`.
