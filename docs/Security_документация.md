# Security-документация приложения Arendo

Команда №5 «ЧЕКЛИ». Аналитик: Коржнев М.Д. Проверки выполнены 27.11.2026.

## 1. Что защищаем

Учётные записи и пароли, личные данные (имя, email, телефон), аренды, штрафы, чёрный список и целостность календаря.

## 2. Список угроз и меры защиты

| Угроза | Что может случиться | Меры защиты |
|---|---|---|
| SQL-инъекция | чтение или порча базы | только параметризованные запросы; проверка типов входных данных; сортировка по списку допустимых значений; роль приложения без прав на изменение схемы |
| XSS | выполнение чужого скрипта, кража токена | React выводит пользовательский текст как текст; Content-Security-Policy разрешает только свои скрипты; сервер принимает только JPEG, PNG и WebP по содержимому файла; заголовок `nosniff` |
| Подбор пароля | захват учётной записи | ограничение частоты входа и регистрации; пароль не короче 8 символов; хэш bcrypt (стоимость 12); одинаковый ответ для неизвестного email и неверного пароля |
| Кража токена | действия от имени пользователя | access-токен живёт 15 минут; refresh меняется при каждом обновлении, а повтор старого отзывает всю сессию; в базе хранятся только хэши; выход и блокировка отзывают сессии |
| Подделка токена | вход без пароля | проверка подписи и срока; сессия проверяется по базе на каждом запросе |
| IDOR | доступ к чужим данным по номеру | проверка владельца ресурса на сервере для аренд, помещений, арендаторов, штрафов |
| Повышение прав | получение роли администратора | роль admin нельзя указать при регистрации; лишние поля отбрасываются; роли проверяются на сервере |
| CSRF | действие от имени пользователя с чужого сайта | токен передаётся в заголовке, а не в cookie, поэтому браузер не подставит его сам; чужие источники не разрешены в CORS |
| Опасная загрузка файлов | исполнение кода, переполнение диска | проверка содержимого, лимиты 5 МБ (фото) и 512 КБ (иконка), не больше 10 фото, случайное имя файла |
| Двойное бронирование | две аренды на одно время | ограничение `EXCLUDE` в базе данных |
| Утечка сведений об ошибках | подсказки атакующему | сообщения без стека и текста запросов; заголовок `X-Powered-By` убран |
| Уязвимые зависимости | известные дыры в библиотеках | `npm audit` в CI и вручную |
| Потеря данных | порча или удаление базы | ежедневная резервная копия, хранение 14 дней |

## 3. Что не защищено

| Что | Риск | Что сделать |
|---|---|---|
| Нет HTTPS: приложение работает на локальном стенде по HTTP | пароли и токены можно перехватить в сети | поставить сертификат перед Nginx до публикации |
| Content-Security-Policy разрешает встроенные стили | возможна подмена оформления при внедрении разметки | убрать встроенные стили или перейти на nonce |
| Токены хранятся в `sessionStorage` | скрипт на странице может их прочитать | перенести refresh-токен в `HttpOnly`-cookie с защитой от CSRF |
| Ограничение частоты только по IP и только на входе и регистрации | распределённый подбор, перегрузка остальных запросов | лимит по учётной записи и общий лимит |
| Регистрация сообщает, что email занят (409) | можно проверить, зарегистрирован ли адрес | подтверждение по почте вместо ответа 409 |
| Отмена чужой аренды отвечает 403, а не 404 | можно узнать, что аренда с таким номером есть | отвечать 404 |
| Swagger UI открыт всем | облегчает изучение API | закрыть в рабочем окружении |
| Нет подтверждения email, восстановления пароля и двухфакторного входа | слабая защита учётных записей | добавить при развитии |
| Резервные копии не шифруются и лежат на том же сервере | утечка или потеря вместе с сервером | шифровать и копировать на другой носитель |
| Нет журнала событий безопасности и оповещений | атаку трудно заметить | писать входы, отказы и блокировки в журнал |

## 4. Как проверяли

Проверки выполнены скриптом на отдельной временной базе с запущенными сервером и клиентом; интерфейс проверен в Chromium.

| Проверка | Фактический результат | Итог |
|---|---|---|
| Регистрация с ролью admin | 422 | отклонено |
| Регистрация с лишним полем статуса | поле отброшено, статус active | пройдено |
| Запрос без токена | 401 | пройдено |
| Мусорный токен, чужой ключ подписи, `alg=none` | 401 | пройдено |
| Просроченный токен с верной подписью | 401 | пройдено |
| Повторное использование refresh-токена | 401, после этого не действуют ни новый refresh, ни access-токен | пройдено |
| Access-токен после выхода | 401 | пройдено |
| Инъекции в поиск (`' OR '1'='1`, `DROP TABLE`, `UNION SELECT`) | 200, найдено 0, данные целы | пройдено |
| Инъекции в сортировку, идентификатор и email | 422 | пройдено |
| Разметка и скрипт в названии помещения | сохраняется и выводится как текст, скрипт не выполняется | пройдено |
| Чужая аренда: чтение и отмена | 404 и 403 | пройдено |
| Чужое помещение: изменение и удаление | 403 | пройдено |
| Чужой арендатор у другого владельца | 404 | пройдено |
| Арендатор в админке и создание помещения | 403 | пройдено |
| Загрузка HTML под видом картинки и файла 6 МБ | 422 и 413 | пройдено |
| Обход пути в загрузках | 404 | пройдено |
| Подбор пароля | после пяти попыток входа в минуту — 429 | пройдено |
| CORS с постороннего сайта | доступ не разрешён | пройдено |
| Заголовки API | `nosniff`, `X-Frame-Options`, `Referrer-Policy`, HSTS | пройдено |
| Content-Security-Policy на страницах | задана; на восьми экранах нарушений и ошибок нет | пройдено |
| Личные ответы | `Cache-Control: no-store` | пройдено |
| Некорректный JSON | 400 без стека | пройдено |
| `npm audit` сервера и клиента | 0 уязвимостей | пройдено |
| Секреты в репозитории | в Git только файлы-примеры `.env.example` | пройдено |
| Права роли приложения в базе | не может менять схему | пройдено |

Не проверялось: сканеры уязвимостей (например, OWASP ZAP), нагрузочные атаки, защита сервера и сети.

## 5. Вывод

Основные угрозы для учебного веб-приложения закрыты и проверены. Перед публикацией в интернете обязательно нужен HTTPS.
