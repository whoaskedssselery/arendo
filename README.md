# Arendo

Веб-приложение для аренды помещений на определённый период: календарь занятости, категории с фото и ценой, отзывы, статусы аренды (Ожидает / Активно / Завершено / Отменено), информация об арендаторах, штрафы, чёрный список и рейтинг.

Стек: PostgreSQL · Node.js (NestJS) · React.

## Быстрый запуск (Docker)

Скопируйте `.env.example` в `.env`, задайте пароли и секрет, затем:

```bash
docker compose up -d --build --wait
```

Сайт: http://localhost:8080 (порт задаёт `WEB_PORT`). Данные хранятся в томах Docker и переживают перезапуск.
`DEMO_PASSWORD` задаёт пароль демонстрационным аккаунтам `admin@arendo.test`, `owner1@arendo.test`, `anna@arendo.test`.
Администратора с настоящим адресом создают переменные `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
Копии БД делаются раз в сутки в том `backups` и хранятся 14 дней.

## Запуск

### Backend

Нужны Node.js 22.9+ и запущенный PostgreSQL 15+. Создайте пустую базу
`arendo`. В каталоге `backend/` создайте `.env` из `.env.example` и укажите
строку подключения в `DATABASE_URL` и секрет подписи в `JWT_ACCESS_SECRET`.
Для генерации случайного секрета можно выполнить
`node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`.
Переменная `PORT` задаёт HTTP-порт (по умолчанию 3000).

Из каталога `backend/` выполните:

```bash
npm ci
npm run build
npm run db:init
npm start
```

`db:init` запускается один раз для пустой базы. Команда применяет схему,
бизнес-логику и демонстрационные данные в одной транзакции. При последующих
запусках достаточно `npm start`.

Swagger UI доступен по адресу [http://localhost:3000/api/docs](http://localhost:3000/api/docs)
и показывает контракт из [docs/api/openapi.yaml](docs/api/openapi.yaml).

Для проверки авторизации зарегистрируйте нового арендатора или владельца через
`POST /api/v1/auth/register`. У демонстрационных аккаунтов в SQL-заполнении
хэши паролей служат заглушками. `POST /api/v1/auth/login` принимает до 5
запросов с одного IP за 60 секунд на экземпляр сервера. Выход без тела запроса
отзывает сессию из access-токена.

NestJS обновляет статусы ожидающих аренд при запуске и затем раз в минуту.

Примеры из кода для защиты и отчёта аналитика собраны в [материалах по паттернам бэкенда](docs/reports/Backend_Patterns.md).

### Серверный кэш

| Маршрут | TTL |
| --- | ---: |
| `GET /api/v1/categories` | 1 час |
| `GET /api/v1/rooms`, включая фильтр свободного периода | 45 секунд |
| `GET /api/v1/rooms/{id}` | 3 минуты |
| `GET /api/v1/rooms/{id}/calendar` | 15 секунд |

Кэш хранит до 2 000 записей в памяти каждого экземпляра NestJS. Ключи учитывают фильтры, сортировку, страницу и период. Создание и редактирование помещения обновляют кэш каталога, а редактирование также сбрасывает карточки и календари. Создание, отмена и завершение аренды сбрасывают календари и выдачу по свободному периоду. Планировщик сбрасывает календари при переходе аренд в активный статус. Изменения, выполненные вне приложения, становятся видны после истечения TTL.

Сервер пишет события `HIT` и `MISS` в журнал. После сборки из `backend/` тесты параллельных чтений можно запустить командой `node --test test/public-cache.test.cjs`. [Журнал интеграционной проверки](docs/reports/benchmarks/server-cache.txt)

### Передача данных по HTTP

Публичные ответы категорий, каталога, карточки и календаря выдают `ETag` и `Cache-Control: public, no-cache`. Перед повторным использованием клиент может проверить сохранённое тело через `If-None-Match`. Публичные JSON-ответы от 512 байт поддерживают gzip. [Замеры размеров и времени HTTP-ответов](docs/reports/Backend_HTTP_Transfer.md)

### База данных

Тесты БД (PostgreSQL-сервер не нужен, используется PGlite):

```bash
cd db/tests && npm i && npm test
```

На настоящем PostgreSQL 15+:

```bash
createdb arendo
psql arendo -v ON_ERROR_STOP=1 --single-transaction -f db/01_schema.sql -f db/02_logic.sql -f db/03_seed.sql
```

### Frontend

Нужен Node.js 22.12+ (или 24 LTS). Backend запускается на порту 3000.

```bash
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. По умолчанию приложение использует настоящий
API через Vite proxy. Для отдельного демонстрационного режима:

```bash
VITE_DEMO_MODE=true npm run dev
```

Демо-аккаунты: `tenant@arendo.test`, `owner@arendo.test`,
`admin@arendo.test`; пароль `Arendo123!`. Они работают только в деморежиме.
В API-режиме зарегистрируйте пользователя; SQL seed содержит заглушки паролей.

```bash
npm run build
npx playwright install chromium
npm test
```

`npm test` запускает демо-UI проверки и обновляет галерею экранов; live-тесты
включаются отдельно. Запуск с реальной БД, кэширование, конфигурация Nginx/CDN,
границы реализации и материалы для команды: [docs/frontend/README.md](docs/frontend/README.md).
